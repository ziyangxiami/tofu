## 本地代码调整

- 相册继续优先验证 ID；当 ID 无效时，只接受豆瓣规范 `/photos/album/<数字>/` 网址作为替代来源。不能恢复、超出安全整数或重复 ID 仍会失败，不随机生成 ID，也不跳过后假报成功。
- 分页继续支持 `data-total-page`；缺少可用属性时，从当前页、可见数字页码和下一页链接推算继续扫描的范围。无法解析仍失败。相册和豆邮核对返回页码与请求页码，拒绝分页中的空内容；豆邮还拒绝重复会话。
- 豆列针对“有效正总量但当前页为空”仅原页重试一次，沿用服务的全局请求间隔。两次都为空则报告总数、页码并失败，不越过缺失页。HTTP 错误、无效总数及错误响应继续明确失败。
- 修正豆邮结束计数不再按每页容量补齐；豆列总量按自建与关注列表的接口总量相加，正常空账号结束计数为 0。
- 诊断新增相册恢复/失败、豆邮分页位置、豆列每页重试次数；仅保存 ID 的类型，不保存原始 ID、网址、Cookie、正文或接口响应内容。

所有任务继续使用既有暂存库和原子发布机制：失败的类别不会替换其已发布快照，其他成功类别可独立发布。
