## Issue #1

原先 `Job.checkin()` 将 `response.redirected` 一律视为未登录，打开最终网址后立即抛错。反馈附件中的 0.13.2 两次运行都在约 0.2 秒内于 `services/Job.js:69` 失败，未进入具体备份任务。附件未包含最终网址，无法还原豆瓣这次重定向的具体原因。

现在允许正常豆瓣 HTTPS 页面重定向，读取最终 HTML，检查有效数字用户 ID、用户接口格式和身份一致性。真正的登录页、安全验证页、异常域名或 HTTP 错误明确停止并提示；不再自动打开新标签。恢复中的任务同时绑定原登录账号和数字目标账号，防止切换账号后沿用旧任务版本。

## 仍存在的问题和验证边界

1. **快照尚非整批原子更新。** 固定主键的数据仍逐条 upsert；后续分页失败时，此前成功行可能已被更新，新版/旧版视图可能部分缺失或混合。将版本标记推迟至成功可以减轻提前切换空版本的问题，无法提供整个旧快照的原子保留。需要影子版本或完整的版本化存储设计才能彻底解决。本次未迁移数据库架构。
2. **真实豆瓣网页和接口仍需浏览器验收。** 离线用例验证代码行为，不证明现时豆瓣的所有 DOM/API、风控、Cookie 策略和已登录账号流程可用。真实 MV3 休眠/唤醒、Chrome IndexedDB 提交和 DNR 生效也未实测。RPC 断线后会明确提示刷新，不重放未知结果的调用。
3. **迁移功能仍未接通。** Explorer 会请求 `migrate/*`，服务任务注册表未启用这些类型。现在会显示不支持并保留窗口，不再静默生成空任务；迁移发布接口、Draft 转换和写入回执未做真实验收。
4. **富文本未完成安全清洗审计。** 浏览界面仍会渲染备份富文本；本次不等于对导入文件、全部 HTML 或第三方库的完整安全审计。
5. **旧 Windows 启动器存在独立问题，未修改。** `GetPrivateProfileString` 的 section 参数为 NULL，会枚举节名；相对 `config.ini` 路径无法可靠读取启动器旁配置。CMake 的输出路径重复拼接、未包含资源文件、WinMain 与控制台目标配置不一致。UNICODE 构建还存在命令行可写内存及 TCHAR/ANSI 混用问题。本机未执行 Windows 构建。参考 [Microsoft INI API](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getprivateprofilestringa)、[CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)、[CMake WIN32_EXECUTABLE](https://cmake.org/cmake/help/latest/prop_tgt/WIN32_EXECUTABLE.html)、[CMake 输出目录](https://cmake.org/cmake/help/latest/variable/CMAKE_RUNTIME_OUTPUT_DIRECTORY.html)。
6. **潜在设置边界。** `Settings.apply` 在遍历嵌套键时复用 target，可能影响后续键；当前配置均为一级属性，未发现现有配置触发。本次未修改。

## 浏览器验收步骤

1. 在 Chrome/Edge 扩展管理页，对原来的解压扩展更新目录并点“重新加载”；关闭旧的豆伴页面后重新打开。不要删除扩展，以免删除其本地备份数据库。
2. 已登录时只选择少量项目开始备份，确认正常跳转不打开新标签，任务能读取账号并完成。
3. 分别验证未登录及豆瓣要求验证的情况，确认显示明确原因且没有写入新备份。
4. 验证恢复任务时切换账号会停止；切回原账号后恢复，完成项目不重复执行。
5. 验证新增广播、多页豆邮、详情失败后的旧正文、下载失败记录，以及数据库导出/导入后再次备份的编号和展示。
