# 服务页数字进度与刷新闪烁修复

日期：2026-11-13。当前为本地未发布改动，扩展版本仍为 0.13.4。

## 原因与改动

原 `ServicePanel.onProgress()` 在等待 `currentJob` RPC 之前先清空任务表，响应后重新创建全部行。每个网络响应都会触发进度事件，因此列表在网络等待期间消失，表格高度缩短，后续内容上移；响应到达后又恢复。服务控制按钮也在等待状态 RPC 前被隐藏。

- 保留任务行和原生进度条节点，仅更新变化的数值、文字与选中状态。等待响应时不清空表格，也不隐藏控制按钮。
- 状态和进度统一读取，刷新轮次串行；同一轮收到多个事件只安排一轮追加读取。持续事件期间仍渲染已经收到的快照，避免一直等待“没有新事件”的窗口。
- 读取失败时保留上次显示并提示；只有成功取得空任务状态才清除旧行。
- 进度条旁显示如 `100 / 167 · 59%` 的数字。初始占位值、缺失或不合法总量、扫描中的评论及公开读书笔记显示 `已处理数 / —`。成功完成的零数据任务显示 `0 / 0 · 100%`。
- 计数沿用既有任务逻辑：黑名单、留言板按页，豆邮按会话预估，其余按条目。数字不等同于最终数据库行数，总量也可能更新；页面已有说明。此次未改动备份执行、数据库、迁移或权限。

## 验证

- `node extension/tests/run.mjs`：10 套离线回归全部通过。新增进度格式、零值、未知总量、连续事件、延迟响应、失败保留与恢复测试。
- 独立 Chrome 157 使用模拟后台加载真实 `options.html`，没有访问豆瓣账号或执行真实备份。
- 连续发送 100 个进度/状态事件：原任务行和进度条节点全部复用，任务表直接子节点增删数为 0，高度变化为 0。包括初始加载在内仅 7 次属性读取。
- 模拟连接失败后保留 12 行与最后显示的数字；成功恢复后隐藏错误提示；正常结束时清空列表并显示“已停止”。
- 390 px 窄屏无横向溢出；浏览器无未处理页面错误。JavaScript 语法及 `git diff --check` 通过。
- 模拟页面截图和浏览器验证结果位于本地 `outputs/service-progress-2026-11-13/`，这些不是用户真实备份数量。

## 实机边界

浏览器工具的 URL 安全策略禁止访问 `chrome-extension://` 页面，因此没有刷新用户当前扩展页，也没有重启正在运行的备份。修改已落在本仓库 `extension/` 中；如果 Chrome 已加载此目录，重新打开或刷新服务设置页可载入前端修改。其他安装目录需要先更新对应扩展文件。本次未打包发布、提交或推送。
